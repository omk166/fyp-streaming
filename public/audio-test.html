Audio test: Off, Browser and Ours

Compare the three microphone processing modes on this computer. All audio stays in this browser. Nothing is uploaded unless you press the button in step 3, which says what it sends first.

Setup

Switches used for Browser and Ours (same meaning as in the meeting)

Off always sends the unprocessed microphone. Ours = DTLN-aec 128 (echo) then DeepFilterNet3 (noise), running in this browser. Use the same microphone, position and volume for every mode.

Ready.

Script

Each recording starts with 3 seconds of silence (to measure the room's noise), then read this aloud at a normal pace:

1 · A/B recording (and noise test)

Record the script once per mode, then play the clips back side by side. For the noise test, either record in your own noisy room, or tick the box to play a noise clip through your speakers while you read (it is not part of any echo reference, so it is treated like room noise).

2 · Echo test

Use speakers, not headphones. The test plays a generated speech-like clip through your speakers as if it came from another participant (through a local WebRTC connection), while you stay completely silent. It records the microphone in each mode and reports how much of the echo remains. Keep the volume the same for all three runs (about 35 seconds in total).

3 · Recognition check (word error rate)

This sends the A/B recordings you made above to the speech service on your own computer (Omnilingual ASR, started with npm run speech), the same recognizer live transcription uses. The speech parts are cut into segments of at most 8 seconds (16 kHz mono WAV) and recognized one by one; the service keeps them in memory only while recognising them and stores nothing. Nothing from this page is uploaded to the meeting server. Each transcript is compared with the script above.

4 · Results

Only values measured on this computer are shown. Anything that could not be measured says why. Published model figures are deliberately not used here.
